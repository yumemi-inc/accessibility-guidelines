<Aside type="tip" title="このガイドラインで目指すこと">
見出しとラベルがコンテンツの目的を明確に伝えることで、ユーザーが情報を効率的に理解し、必要な情報へ素早くアクセスできるようにします。

- スクリーンリーダー利用者が内容を素早く把握できる
- 認知的な負荷を軽減して使いやすくする
</Aside>

## このガイドラインが達成されないとどうなるか

<Aside type="caution">
曖昧な見出しやラベルは、ユーザーが目的の情報を見つけられず、フォーム入力でミスを引き起こす原因となります。
</Aside>

結果的に、サービスの利用効率が低下し、ユーザー体験が大きく損なわれます。

<Card title="具体例：ECサイトでの困りごと" icon="information">
Eさんはオンラインで商品を購入しようとしていました。
しかし、「詳細」「その他」「こちら」といった曖昧な見出しやリンクが多く、
どこをクリックすれば商品仕様が見られるのか分からず、
結局購入を諦めて他のサイトで購入しました。
</Card>

<Aside type="danger" title="こんなとき、達成されていないかもしれません">
- 見出しが「詳細」「その他」など曖昧
- フォームのラベルが「入力1」「入力2」のような意味のない名前
- リンクテキストが「こちら」「詳しくはこちら」だけ
- ボタンがすべて「送信」「次へ」で区別できない
- 同じページ内に同じ見出しが複数ある
</Aside>

## 最低限、すぐに取り組めること

### 要件定義

- コンテンツ構造と見出し階層を設計する
- フォームの各項目の説明を明文化する

### デザイン

- 見出しのビジュアル階層を定義する
- ラベルとヒントテキストのスタイルを統一する

### 開発

- 意味のある見出しテキストを使用する
- フォームラベルを必ず関連付ける
- リンクテキストを具体的にする

<Card title="最小限の実装例" icon="approve-check">

<LiveCodeExample
  html={dedent`
    <!-- 見出しの階層構造 -->
    <h1>サービス名</h1>
    <h2>主要機能</h2>

    <h3>機能B：共有設定</h3>
    
    <!-- 明確なフォームラベル -->

### QA

- スクリーンリーダーで見出しジャンプが機能するか確認
- フォーム入力時にラベルが読み上げられるか確認
- リンクテキストだけで行き先が分かるか確認

### リリース後

- ユーザーからの「分かりにくい」というフィードバックを収集
- アナリティクスで離脱率の高いページを特定

## チェックリスト

### 必ず対応（高優先度）

<Aside type="caution" title="必須チェック項目">
- [ ] **見出し**がコンテンツを正確に表現している
- [ ] **フォームラベル**が入力内容を明確に説明している
- [ ] **リンクテキスト**が遷移先を具体的に示している
</Aside>

<Aside type="note" title="推奨項目（中優先度）">
- [ ] **見出し階層**が論理的に構成されている
- [ ] **エラーメッセージ**が具体的な修正方法を示している
- [ ] **ボタンテキスト**が実行される動作を明確に表現している
</Aside>

### 関連項目（別ガイドライン対象）

- [ ] **見出し構造**が適切にマークアップされている（1.3.1）
- [ ] **ラベル**が入力フィールドと関連付けられている（1.3.5）

## 知っておくと便利なこと

### 良い見出しの特徴

| 特徴 | 悪い例 | 良い例 |
|------|--------|--------|
| 具体的 | 「情報」 | 「営業時間」 |
| 簡潔 | 「お客様へのお知らせ事項について」 | 「お知らせ」 |
| 独立して理解可能 | 「詳細」 | 「製品仕様」 |
| 一貫性がある | 「価格」「料金」「費用」が混在 | 「料金」で統一 |

<Aside type="tip" title="スクリーンリーダーでの見出しナビゲーション">
多くのスクリーンリーダーユーザーは、見出しジャンプ機能を使って素早くコンテンツを把握します。

- NVDA/JAWS: Hキーで次の見出しへジャンプ
- VoiceOver: ローターで見出しナビゲーション
- 見出しリストを表示して全体構造を把握

明確な見出しは、この機能の効果を最大化します。
</Aside>

### フォームラベルのベストプラクティス

```html title="包括的なラベル設計"
<div class="form-group">
  <label for="password">
    パスワード
    <span class="required">必須</span>
  </label>
  <input 
    type="password" 
    id="password"
    aria-describedby="password-hint"
    required>
  <small id="password-hint">
    8文字以上、英数字を含む
  </small>
</div>
```
